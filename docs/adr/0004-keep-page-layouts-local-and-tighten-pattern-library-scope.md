# Keep page layouts local and tighten pattern-library scope

This ADR supersedes the shell-specific guidance in ADR-0002. Text2Ink will keep the **Component Library** and the **Pattern Library** as separate layers, but only genuinely reusable multi-component UX solutions belong in the **Pattern Library**. Route-specific or feature-specific page layouts stay local to those surfaces even when they share header or footer components, gutters, widths, or other **Design Tokens**; shared layout values and same-role control sizing are standardized through **Design Tokens** and shared components rather than speculative shell abstractions. A layout or flow should be promoted into the **Pattern Library** only when real cross-surface reuse is evident or a concrete second consumer is in scope, not simply because multiple pages happen to share spacing or chrome.
